<section_guide number="2" title="MVP Goals and Key Metrics">
<purpose>Define 2-5 measurable goals to validate the MVP hypothesis</purpose>

<questions>
1. What is the core hypothesis you want to validate with the MVP?
2. Define 2-5 measurable goals to validate this hypothesis
3. What are the baseline (current) and target values for each goal?
</questions>

<note>
If the user already stated a success signal in 1.6 Success Criteria, reference it and turn it into a measurable KPI here rather than re-asking. 1.6 is the high-level (possibly qualitative) product-success signal; Section 2 is where it becomes a number with a baseline and target.
</note>

<tension_metrics>
A KPI is a proxy for the MVP hypothesis. An agent that later optimizes one KPI alone can reach its target while defeating the purpose. Users usually supply KPIs but rarely think of their tension metrics, because those come from imagining abuse or the opposite failure. So for every KPI, always derive a scenario that reaches its target while defeating the purpose (abuse, shortcut or opposite failure), and propose a tension metric that protects the same purpose and worsens in that scenario. State the scenario. Another KPI may already serve as the tension; point that out instead of adding a duplicate.
The user decides adoption: accept, revise or decline. Do not invent a target the user did not give or block completion on a declined candidate. An adopted tension is monitoring-only unless the user confirms it as a required success condition.
</tension_metrics>

<example>
### 2.1 Purpose
- Can AI quickly generate technical specification documents based on a given template, reflecting user input?

### 2.2 Key Performance Indicators (KPIs)

- Average time for a user to complete a document via AI: **under 30 minutes**
- Conversation context retention rate: **90% or higher**
  - Also the tension metric for writing time: finishing faster by dropping supplied context lowers it.
    </example>
