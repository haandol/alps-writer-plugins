<section_guide number="1" title="Business Context">
<purpose>Capture the target user, the core problem, the intent, and the desired outcome that bound every later proposal.</purpose>

<questions>
1. Who is the main target user, and what core problem should the product address?
2. What should change for that user, what final outcome should they gain, and why does it matter to the business?
</questions>

<workflow>
Ask one question at a time, or both only when the user can answer them together easily. Integrate
the answer before asking for the next missing item.

Keep Section 1 to two inputs. Target User and Core Problem names the main user and the problem.
Intent and Desired Outcome states the intended change, the final outcome, why it matters, and any
priorities or scope boundaries the user supplied. Preserve a measurement signal the user already
has; Section 6 turns it into a KPI with a tension metric. Do not require a signal or start a
metrics interview.

Do not ask for a solution, screen, technology, requirement list, starting state, demo procedure,
FAQ, architecture, or implementation plan. Use one short statement for each input unless the user
already supplied more detail.
</workflow>

<completion required="true">Confirm Target User and Core Problem and Intent and Desired Outcome before saving 1.1-1.2 separately.</completion>
</section_guide>
