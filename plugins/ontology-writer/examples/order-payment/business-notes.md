# 주문·결제 업무 자료

이 자료는 Ontology Writer의 사용법을 설명하기 위해 작성한 가상의 상점 예제다. 실제 프로젝트의 업무 정책이나 사용자 승인 기록이 아니다. 아래의 보드와 모델도 이 자료를 바탕으로 작성한 학습용 후보이며, 실제 에이전트의 생성 실험 결과는 아니다.

<a id="scope"></a>

## 업무 범위와 책임

고객이 주문을 접수한 시점부터 대금을 결제하고 주문 확정 결과를 확인할 때까지를 다룬다. 배송과 환불은 이 예제의 범위 밖이다.

주문 관리는 고객의 구매 요청과 주문 확정을 책임진다. 결제 처리는 해당 주문의 결제 요청과 수납 결과를 다룬다. 외부 결제 제공자의 내부 처리는 이 상점이 구현하는 기능의 범위 밖이다.

주문과 결제 내역은 각각 식별자로 구별하는 업무 대상이라고 가정한다. 어떤 데이터를 한 번에 일관되게 변경해야 하는지에 대한 애그리거트 경계는 아직 정의하지 않았다.

<a id="business-areas"></a>

### 예제의 업무 영역

이 학습 예제의 도메인 이름은 **온라인 상점**이다. 구매 요청을 접수하고 확정하는 **주문 운영**은 핵심 서브도메인,
대금 수납을 다루는 **대금 결제**는 지원 서브도메인으로 가정한다. 주문 관리 컨텍스트는 주문 운영에,
결제 처리 컨텍스트는 대금 결제에 속한다. 이 분류는 이 가상 상점의 예시이며, 실제 프로젝트의 중요도를 판정하는 규칙이 아니다.
외부 결제 제공자는 수행 주체로만 기록했다. 그 사실만으로 별도의 외부 컨텍스트나 소속을 확정하지 않는다.

<a id="normal-flow"></a>

## 정상 흐름

| 수행자           | 행동      | 업무 대상의 변화               | 발생한 업무 사건                      |
| ---------------- | --------- | ------------------------------ | ------------------------------------- |
| 고객             | 주문 접수 | 주문이 없음 → 결제 대기        | 주문 접수됨                           |
| 고객             | 결제 요청 | 결제 요청이 없음 → 결제 요청됨 | 별도의 사건 이름은 아직 기록하지 않음 |
| 외부 결제 제공자 | 대금 결제 | 결제 요청됨 → 결제 완료        | 결제 완료됨                           |
| 주문 처리 시스템 | 주문 확정 | 결제 대기 → 주문 확정          | 주문 확정됨                           |

이 표의 전후 상태는 예제 자료에 명시한 값이다. 보드에는 표시할 수 있지만, 저장 온톨로지에 새로운 상태 속성을 추가한다는 뜻은 아니다. 실제로 구현할 상태와 전이는 ADR의 요구사항으로 확정해야 한다.

<a id="views"></a>

### 행동에 참고하고 결과를 확인하는 뷰

고객은 **주문서**에서 구매 항목과 금액을 확인한 뒤 주문을 접수하고, **결제 선택 화면**에서 해당 주문과 결제 수단을
확인한 뒤 결제를 요청한다. 주문이 확정되면 고객은 **주문 현황**에서 확정 결과를 확인한다. 이 세 뷰는 화면 또는
조회 모델의 역할을 설명하기 위한 예제 자료다. 뷰가 사건을 직접 발생시키거나 어느 사건만으로 즉시 갱신된다고 정하지 않았다.

외부 결제 제공자의 대금 결제와 시스템의 주문 확정은 사람의 화면 조작을 전제로 하지 않는다. 대금 결제의 뷰,
주문 접수 직후의 결과 뷰와 자동 처리의 입력 뷰는 이 자료에 기록하지 않았다.

<a id="policies"></a>

## 사건에 반응하는 정책과 규칙

- 주문 접수됨 사건이 발생하면, 해당 주문에 아직 결제가 없을 때 결제 요청을 시작한다. 이 예제에서 상점이 선택한 업무 정책이다.
- 결제 완료됨 사건이 발생하면, 완료된 결제가 확정하려는 주문의 결제일 때 주문 확정을 시작한다. 대금 결제가 끝나기 전에 주문을 확정하지 않는 상점 운영 정책을 따른다.
- 수납한 금액은 해당 주문의 금액과 같아야 한다. 주문과 결제에 함께 적용하는 회계 규칙이다.

주문 접수와 주문 확정 사이, 결제 요청과 대금 결제 사이에는 진행 순서가 있다. 이 순서 표시를 사건의 원인이나 전달 조건으로 대신하지 않는다.

<a id="open-questions"></a>

## 아직 정하지 않은 내용

- 결제가 실패한 주문을 취소할지, 결제를 기다리는 상태로 둘지는 정하지 않았다.
- 카드 결제가 거절된 뒤 누가 어떤 방식으로 재시도를 시작하는지, 재시도 횟수와 대기 시간은 정하지 않았다.
- 이미 처리한 결제 완료 사건을 다시 받았을 때 주문 확정 기능이 어떻게 응답할지는 정하지 않았다.

이 내용은 확인할 질문이다. 정상 흐름이나 상태 이름만으로 실패 분기, 자동 취소 또는 중복 처리 보장을 확정하지 않는다.
