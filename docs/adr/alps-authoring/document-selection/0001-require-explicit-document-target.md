# ADR 0001: 문서별 요청에 편집 대상을 명시

Date: 2026-10-05

## Status

Accepted (2026-10-05)

## Purpose

여러 문서의 작성 작업을 한 도구 연결에서 번갈아 수행할 때, 마지막으로 연 문서를 다음
요청의 대상으로 사용하면 앞서 준비한 내용이 다른 문서에 저장될 수 있다. 호출자는 과거
요청 순서를 기억해야만 현재 작업 대상을 판단할 수 있다. 각 요청에서 대상을 확인하고,
다른 문서를 열거나 읽는 작업이 이미 준비한 편집의 대상을 바꾸지 않도록 한다.

## Decision Drivers

- 다른 문서의 생성·열기·읽기가 준비된 편집의 대상을 바꾸면 안 된다.
- 문서 본문, 용어 정의, 작성 상태와 내보내기가 같은 대상 선택 규칙을 따라야 한다.
- 대상이 빠지거나 유효하지 않은 요청은 문서를 변경하기 전에 실패해야 한다.
- 문서 형식, 프로필별 검증과 내용 승인은 기존 계약을 유지해야 한다.

## Decision

문서에 종속된 모든 요청은 대상 문서를 명시한다. 생성 요청은 생성 위치를 지정하고,
열기·본문 읽기와 저장·용어 읽기와 저장·작성 상태 조회·내보내기는 원본 문서를 지정한다.
서버는 다른 요청에서 선택한 문서를 대상의 기본값으로 사용하지 않는다. 요청에 대상이
없으면 실패를 반환한다. 대상이 존재하는 유효한 문서라면 사전 열기 요청 없이 사용할 수
있다.

대상 문서를 요청과 결합하면 서로 다른 문서 작업의 순서가 대상 선택에 영향을 주지 않는다.
이 때문에 대상 생략 호출의 호환성을 유지하는 선택을 채택하지 않는다. 이 결정은 서로
다른 문서의 선택을 분리하며, 같은 문서에 대한 여러 작성자의 충돌 해결 방식을 정하지 않는다.

### Requirement contract

| 의무                                                                 | 관찰 가능한 검증 기준                                                                         |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 문서별 요청은 생성 위치 또는 대상 원본 문서를 필수로 지정한다.       | 대상 없는 요청은 실패하고 어떤 문서도 변경하지 않는다.                                        |
| 유효한 대상 문서에 대한 요청은 이전 요청의 대상과 무관하게 동작한다. | 두 문서를 번갈아 생성·열기·조회한 뒤 첫 문서를 지정해 저장하면 첫 문서만 변경된다.            |
| 대상 문서는 사전에 열지 않아도 각 요청에서 검증해 사용할 수 있다.    | 새 연결에서 기존 문서를 지정해 읽고 저장할 수 있다.                                           |
| 잘못된 대상이나 프로필 검증 실패는 다른 문서로 전환하지 않는다.      | 존재하지 않거나 유효하지 않은 문서를 지정한 요청이 실패하며 다른 문서는 그대로다.             |
| 본문·용어·상태·내보내기는 지정한 원본만 사용한다.                    | 두 문서에 서로 다른 내용과 용어를 넣었을 때 각 요청과 내보내기에 해당 문서의 결과만 나타난다. |
| 문서 형식과 프로필별 검증·내용 승인 규칙은 유지한다.                 | 기존의 유효한 두 프로필 문서를 다시 쓸 수 있고 잘못된 내용은 저장되지 않는다.                 |

### Alternatives

- **연결마다 한 활성 문서를 사용한다.** 기존 호출이 간단하지만 다른 작업이 대상을
  변경할 수 있어 호출 순서를 알아야 한다.
- **대상을 선택적으로 지정한다.** 기존 호출과 명시적 호출을 함께 지원하지만 대상을
  생략한 경로에는 같은 혼동이 남는다.
- **모든 문서별 요청이 대상을 지정한다.** 호출마다 대상이 분명하고 작업 순서의 영향을
  받지 않는다. 기존 호출자는 대상 입력을 추가해야 한다.

## Consequences

### Positive

- 문서별 작업을 섞어도 각 요청의 대상이 유지된다.
- 대상 누락과 잘못된 대상은 문서 변경 전에 드러난다.

### Negative

- 대상 입력을 생략하던 호출자는 변경된 도구 계약에 맞춰야 한다.
- 호출자는 문서 경로를 각 요청에 전달해야 한다.

### Risks

- 호출자가 명시적으로 잘못된 유효 문서를 지정하는 오류까지 자동으로 판단하지는 못한다.
- 같은 문서를 여러 연결에서 동시에 수정하는 충돌은 별도 검토가 필요하다.
