# ADR 0001: 파괴적 ADR rollup은 명시적 승인을 요구

Date: 2026-09-07

## Status

Accepted (2026-09-07)

## Context

ADR rollup은 파일을 덮어쓰고 삭제하거나 번호를 다시 매길 수 있다. renumber는 저장소 밖의 영구 링크를 끊을 수 있으므로 무응답이나 모호한 응답을 승인으로 해석하면 복구하기 어려운 변경이 발생한다.

하네스는 파괴적 범위와 결과를 보여준 뒤 명시적 승인을 받아야 하며, 승인 증거가 없으면 현재 파일과 번호를 유지해야 한다.

## Decision Drivers

- 파일 삭제·덮어쓰기·경로 변경은 사용자 의도 없이 실행되면 안 된다.
- 무응답과 모호한 응답은 파괴적 변경의 승인 증거가 아니다.
- rollup은 승인된 범위만 바꾸고 나머지 category와 번호를 보존해야 한다.

## Decision

ADR rollup은 덮어쓸 파일, 삭제할 파일과 모든 old → new 경로를 보여주고 명시적으로 승인된 파괴적 변경만 실행한다.

사용자가 응답하지 않거나 renumber 여부를 명확히 선택하지 않으면 번호 gap을 유지한다.

### Requirement contract

- 승인 화면은 덮어쓸 파일, 삭제할 파일과 모든 경로 변경을 표시한다.
- 승인된 category와 파일만 변경한다.
- 무응답·모호한 응답에서는 파일, 번호와 매핑을 변경하지 않는다.
- renumber를 승인하지 않으면 기존 번호와 gap을 유지한다.

### Alternatives

1. **무응답 시 gap 자동 정리**
   - 장점: 번호가 연속적이다.
   - 단점: 외부 링크를 끊는 rename을 승인 없이 실행한다.
2. **모든 gap 유지**
   - 장점: 경로가 안정적이다.
   - 단점: 사용자가 원하는 정리도 할 수 없다.
3. **명시 승인된 renumber만 실행**
   - 장점: 경로 안정성과 정리 선택권을 함께 보존한다.
   - 단점: 파괴적 변경 전에 승인 단계가 필요하다.

## Consequences

### Positive

- 무응답이 파괴적 변경으로 이어지지 않는다.
- 사용자는 삭제와 경로 변경 범위를 승인 전에 확인한다.

### Negative

- 번호 gap을 제거하려면 명시적 선택이 필요하다.

### Risks

- 승인 화면이 경로 변경을 누락할 수 있다. deterministic plan과 최종 lint가 표시 대상과 실제 변경을 대조해야 한다.
