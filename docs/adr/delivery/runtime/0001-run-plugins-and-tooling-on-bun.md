# ADR 0001: 플러그인 실행물과 저장소 개발 도구를 Bun 하나로 통일

Date: 2026-11-07

## Status

Accepted (2026-11-08)

## Purpose

플러그인은 사용자 환경에서 MCP 서버, 세션 시작 훅과 스킬이 실행하는 스크립트를 돌리고, 저장소는 의존성 설치,
테스트, 빌드와 릴리스 도구를 돌린다. 이 둘이 서로 다른 런타임과 패키지 관리자를 요구하면 사용자와 기여자는 여러
도구를 설치하고 버전을 맞춰야 하며, 어떤 동작이 어느 런타임에서 깨지는지도 따로 확인해야 한다.

사용자는 플러그인 실행물과 저장소 개발 도구 전체를 Bun 하나로 실행하기를 원한다. Node와 별도 패키지 관리자를
요구하지 않고, 그 대가로 Bun이 없는 환경에서는 플러그인과 저장소 도구가 동작하지 않는 것을 받아들인다.

## Decision Drivers

- 사용자와 기여자는 하나의 런타임만 설치하고 관리해야 한다.
- 매니페스트, 훅 설정, 스킬 명령, 문서, 패키지 스크립트와 CI가 같은 런타임을 가리켜 안내와 실제 실행이 어긋나지 않아야 한다.
- 배포 전에 실제 사용자 런타임으로 실행물을 검증해야 한다.
- 런타임을 바꿔도 의존성 보안 고정과 테스트가 지키던 동작은 약해지지 않아야 한다.

## Decision

사용자 환경에서 실행되는 플러그인 실행물 — alps-writer MCP 서버, 각 플러그인의 세션 시작 훅, 스킬과 문서가
실행하라고 안내하는 플러그인 스크립트 — 은 Bun으로 실행한다. 플러그인 매니페스트, 훅 설정, 스킬 명령, 문서의
명령 예와 스크립트의 실행 선언이 모두 Bun을 가리킨다. 사용자 설치 요구사항은 Bun 1.4.2 이상 하나다.

저장소 개발 — 의존성 설치, 테스트, 타입 검사, 번들, 린트·포맷, 동기화·버전·릴리스 스크립트와 git hook — 도
Bun 1.4.2 이상으로 실행한다. 의존성은 Bun의 패키지 관리자와 그 잠금 파일로 관리하고, 테스트는 Bun의 테스트
러너로 실행한다. 저장소를 설치·테스트·빌드하는 데 Node와 별도 패키지 관리자가 필요하지 않다.

의존성 보안 고정은 Bun 설치에서도 같은 최소 버전을 강제한다. 특정 버전 범위만 올리는 고정을 Bun이 표현하지 못하면,
그 패키지 전체를 고정 버전 이상으로 올린다. 이 때문에 다른 주 버전을 요구하던 의존 패키지가 있으면 그 패키지를
쓰는 테스트로 동작을 확인한다.

Bun이 없으면 실행물과 저장소 도구는 시작하지 않고, 다른 런타임으로 자동 전환하지 않는다. 런타임 하나로 동작과
오류를 판단하기 위해서다. 설치 안내와 기여 안내가 Bun 요구사항을 먼저 밝힌다. 필수 CI는 Bun만 설치해 테스트·빌드를
실행하고, MCP 서버, 세션 시작 훅과 플러그인 스크립트를 Bun으로 실행해 배포물을 확인한다.

### Requirement contract

#### Required guarantees

| 의무                                                                                                                                                     | 관찰 가능한 검증 기준                                                                                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1. MCP 서버 설정, 세션 시작 훅 설정, 스킬 명령과 문서의 플러그인 스크립트 실행 예는 Bun으로 실행한다.                                                   | 플러그인 매니페스트, 훅 설정, 스킬과 사용자 문서에 플러그인 실행물을 Node로 실행하라는 명령이 없다.                                                                  |
| R2. 플러그인과 저장소 스크립트, 훅의 실행 선언은 Bun을 가리킨다.                                                                                         | 직접 실행 가능한 스크립트와 훅의 첫 줄 실행 선언이 Bun이다.                                                                                                          |
| R3. 사용자 설치 요구사항과 기여 요구사항은 Bun 1.4.2 이상이며, 설치·기여 안내는 이 요구사항을 밝힌다.                                                    | 설치와 기여 안내에 Bun 1.4.2 이상이 요구사항으로 적혀 있고, Node나 별도 패키지 관리자가 요구사항으로 적혀 있지 않다.                                                 |
| R4. 저장소의 의존성 설치, 테스트, 타입 검사, 번들, 린트·포맷, 동기화·버전·릴리스 스크립트와 git hook은 Bun과 Bun의 패키지 관리자·테스트 러너로 실행한다. | 저장소에는 Bun 잠금 파일만 있고, 패키지 스크립트·git hook·CI 명령이 Node, npx나 별도 패키지 관리자를 호출하지 않으며, Bun만 있는 환경에서 설치·테스트·빌드가 끝난다. |
| R5. 의존성 보안 고정은 Bun 설치에서도 고정한 최소 버전 이상을 설치한다.                                                                                  | 잠금 파일의 고정 대상 패키지가 모두 고정 버전 이상이고, 다른 주 버전을 요구하던 의존 패키지를 쓰는 테스트가 통과한다.                                                |
| R6. 필수 CI는 Bun만 설치해 테스트와 빌드를 실행하고, MCP 서버의 초기화 응답과 세션 시작 훅을 Bun으로 확인한다.                                           | 필수 CI 작업에 Node 설치 단계가 없고, 런타임 검증 단계가 MCP 서버와 훅을 Bun으로 실행한다.                                                                           |

#### Prohibitions

| 의무                                                                           | 관찰 가능한 검증 기준                                                                          |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| R7. Bun이 없을 때 실행물과 저장소 도구는 다른 런타임으로 자동 전환하지 않는다. | 매니페스트, 훅 설정과 패키지 스크립트가 Bun 실패 시 다른 런타임을 실행하는 명령을 담지 않는다. |
| R8. 런타임 전환은 테스트가 확인하던 동작이나 테스트 범위를 줄이지 않는다.      | 전환 전에 실행되던 테스트 파일이 Bun 테스트 러너에서도 모두 실행되고 통과한다.                 |

### Alternatives

1. **실행물과 개발 도구 모두 Node와 pnpm**
   - 장점: 기존 설정과 잠금 파일을 그대로 쓰고, 범위별 보안 고정을 표현할 수 있다.
   - 단점: 사용자가 원한 Bun 단일 런타임과 맞지 않는다.

2. **실행물은 Bun, 개발 도구는 Node와 pnpm**
   - 장점: 사용자는 Bun 하나만 설치하고, 개발 도구 설정은 바꾸지 않는다.
   - 단점: 기여자는 두 런타임과 별도 패키지 관리자를 설치해야 하고, 테스트가 사용자 런타임과 다른 런타임에서 실행된다.

3. **실행물과 개발 도구 전체를 Bun으로 실행 (채택)**
   - 장점: 사용자와 기여자가 Bun 하나만 설치하고, 테스트와 배포 검증이 사용자 런타임과 같은 런타임에서 실행된다.
   - 단점: Bun이 없으면 아무것도 동작하지 않고, 범위별 보안 고정은 패키지 전체 고정으로 넓어진다.

## Consequences

### Positive

- 사용자와 기여자는 Bun 하나만 설치하고 관리한다.
- 매니페스트, 훅, 스킬, 문서, 패키지 스크립트와 CI가 같은 실행 방법을 안내한다.
- 테스트가 사용자와 같은 런타임에서 실행물을 검증한다.

### Negative

- Bun이 없는 환경에서는 세션 시작 지침, MCP 서버, 스크립트와 저장소 도구가 모두 동작하지 않는다.
- 범위별 보안 고정을 쓸 수 없는 패키지는 다른 주 버전 의존 패키지까지 같은 버전으로 올라간다.

### Risks

- Bun의 Node 호환 모듈이나 테스트 러너가 다르게 동작하는 부분이 있을 수 있다. 전환 전 테스트를 모두 Bun 테스트 러너에서 통과시키고, 필수 CI가 같은 런타임으로 검증한다.
